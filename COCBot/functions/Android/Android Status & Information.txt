Generic (any ADB-reachable Android)
===================================
Not an emulator product: this is any Android that already answers on ADB and that the bot does
not install, launch or own a window for.
MyBot Command Line Key: Generic
Default Instance Key: Android
Intended for:
  - an Android Studio AVD or Waydroid on Linux, with the bot itself running under Wine
  - a physical device, or any emulator running outside the bot's own Windows session
Requirements:
  - start the Android yourself BEFORE the bot; the bot never starts or stops it
  - the device must appear as "device" in: adb devices
    (for a host:port device the bot issues "adb connect" itself)
  - screen must be the resolution the bot expects; "Configure Android Screen" does this over
    ADB with "wm size" / "wm density 160"
Differences from the Windows emulators:
  - no window at all, so no Dock Mode and no WinAPI/DirectX background mode; capture is always
    ADB screencap ("background mode 2")
  - no host<->Android shared folder, so captures, scripts and the toybox/minitouch binaries are
    moved with "adb pull"/"adb push" instead (see $g_bAndroidAdbNoSharedFolder). Expect capture
    to be slower than on an emulator with a real shared folder.
  - the touch input device is found by "getevent -p", falling back to the first device whose
    ABS_MT_POSITION_X/Y maxima match the expected screen size
Set a non-default device with $g_sAndroidAdbGenericDevice, e.g. "emulator-5554" for an AVD.
See COCBot\functions\Android\AndroidGeneric.au3.

Feature & Functions Notes
-------------------------
DPI Support*: DPI Awareness is available for all Android Emulators, but is different depending on the Android Emulator and background settings and dock mode.
When Android is running in DPI Aware Mode (bot by default is running in DPI un-aware mode) docking and non background mode will turn bot also into DPI Aware
Mode, resulting in smaller Window scaled at 100%. Also, when Android is running in DPI un-aware mode (e.g. iTools), docking will not change anything, only when
disabling background mode.

AndroidSendText*: Works only for ASCII Characters, most symbols, but no Umlauts etc.
It falls back to WinAPI when unsupported characters are detected, but might fail also.
If sending text is not working, keep it empty in bot and last entered text will be sent.

AndroidClick*: Can be only enabled in config.ini, use adb.click.enabled=1 and adb.clicks.enabled=1
